Explorer theme studies

The Explorer page drawn in four component-library looks and five "vibe" themes. Every version is the same markup with a different set of theme tokens: colors, corner shape, borders, fonts, heading style and a background texture. The board and the tree window keep their own colors in every one, because themes change the surroundings and leave the visualizations alone.

Which framework fits themes

What matters for user-picked themes is less the library's look than whether every visual decision is a token the theme can replace. Behavior (menus, dialogs, tooltips, focus and keyboard handling) is what a library should supply.

What a theme can change

  • Color: page, sidebar, cards, text, muted text, accent, borders.
  • Shape: corner radius per size, border width and style (double rules for the study), cut corners (space).
  • Type: display, body and label faces, heading case and letter spacing.
  • Texture and ornament: a page background image, a card frieze or edge.
  • Depth: shadows, or none.

What a theme never touches

  • The board and its squares, pieces and arrows.
  • The visualizations: the book views, the Treemap and the Labyrinth keep their own tokens (--view-*, --fam-*), and a theme can only frame them.
  • Layout: the same page structure in every theme, so tests and screenshots stay meaningful.

A path from here

  1. Gather today's tokens (--bg-*, --text-*, the btn-* utilities) into one theme file, and add shape and type tokens.
  2. Add shadcn/ui and move controls over one by one: Button, Select, Tabs for the view rail, Tooltip, Dialog, Dropdown menu.
  3. Write each theme as a data-theme block; the five background modes become color variants or fold into themes.
  4. Load a theme's fonts only when it is picked, and add the picker to Settings.
